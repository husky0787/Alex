# Preserve source sightings separately from immutable price versions

Task 3 extends ADR 0001: valid rows publish even when other rows are quarantined, and legacy analysis is disabled now rather than allowing random or untraceable prices until task 5. Task 5 will replace this temporary guard with validated, immutable portfolio price snapshots; it must not simply turn the legacy flow back on.

Keep one immutable version per normalized bar content and a separate run-to-version sighting for every successful observation. This makes an A→B→A correction show the latest A without duplicating A or losing B. Recovery retains the original observation time so loading an older saved response cannot override a newer source sighting. Prices, sightings, quarantine references and terminal run status commit together. `completed_through` is per-run contiguous trading-session coverage, not a global maximum date; later scheduling must not skip unresolved gaps based on the latest visible price.

Serialize ingestion for each source/symbol using a PostgreSQL session advisory lock across acquisition and publication. A competing run fails explicitly with `symbol_busy` and makes no provider request; the operator can retry after the owner finishes. Session locks release on disconnect. Use direct PostgreSQL connections (not a transaction-pooling proxy) for this operator pipeline. Resume only after acquiring the same lock; terminal runs are immutable and explicit retries create linked runs.

Raw objects and the database cannot commit atomically. Each HTTP attempt retains its own immutable raw response; a crash before its pointer commits can leave an orphan. Resume never searches for arbitrary orphan objects: it verifies the digest of a committed successful response, or consumes the remaining HTTP attempt budget. A recorded but unfinished attempt consumes a slot. Operators can inspect attempts and quarantine locally; these paths and error bodies are never exposed through the user price API.

Transient transport errors and HTTP 408/429/500/502/503/504 get at most three attempts. Backoff is bounded and a valid Retry-After above 60 seconds stops the run rather than retrying earlier than requested. Validation/auth errors are terminal. Database commit uncertainty is resolved by reading the run on a new connection; no blind automatic replay of writes. Deploying the migration and recovery commands to AWS remains a separate task.
