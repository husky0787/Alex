# Freeze analysis inputs in the job before queueing

Store a server-created price snapshot in the job's existing request payload, containing owned holdings, cash, preferences and exact verified price/version provenance. All analysis agents load that same snapshot and never refresh or overwrite global instrument prices. Copying values alongside immutable observation references allows existing Data API Lambda agents to read their job without adding direct market-database access to every agent; keeping only version IDs would couple every report execution to the market database.

The API builds the snapshot before job creation or SQS delivery, rejects missing/unsupported required holdings, and permits stale prices with deterministic report/UI disclosure. Market reads share a repeatable-read transaction; holdings read through the existing Data API are frozen as observed, without claiming a transaction across the two database interfaces. The snapshot is write-once through application paths, and a content digest detects accidental edits, not malicious database writers. Existing report update operations change only output columns. Legacy jobs without snapshots cannot be re-executed as verified reports.

SQS and job insertion remain separate operations: a known send failure marks the job failed and returns non-success; ambiguous delivery may still invoke a worker, which always uses the persisted snapshot. Queue delivery deduplication and broader workflow exactly-once semantics are outside this decision. The existing analysis guard is replaced only on paths with a validated snapshot, including direct child-agent invocations; externally supplied portfolio overrides are ignored.
