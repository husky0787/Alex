# Reproduce the portfolio showcase

This runbook connects the real Next.js/FastAPI/Clerk flow to isolated AWS workers and a separate application database. It does not replace the original application. The market database and frontend/API run locally; use the [EKS runbook](../eks/README.md) to reproduce Task9's different deployment. Read the [acceptance record](../../docs/verification/task-11-showcase.md) and [cloud allowance](../../docs/verification/task-11-cloud-window.md) first.

## Prerequisites and ownership

Use Python3.12, uv on PATH, Node24/npm, PostgreSQL17 tools, AWS CLI with browser-login support, and Terraform1.7+ (tested1.16.4). Docker running Linux amd64 containers is needed only to rebuild the Reporter dependency ZIP; a previously built, privately transferred and independently hash-verified ZIP can be reused. No Docker credentials or AWS secrets belong in the image.

You need an existing Aurora PostgreSQL cluster with Data API and an admin secret, a real Clerk application with localhost allowed, and the configured Massive/Polygon key. The recorded operator profile is `alex-task09`; the normal runtime uses `default`. Configure these profiles for your own account, or change the helper's explicit profile selection. Do not copy somebody else's credentials.

Keep `.local/`, `.planning/`, `.env`, database dumps and all Terraform state private. Restrict `.local/` to the current user. On POSIX use `umask 077` before setup; on Windows retain an owner-restricted checkout ACL. Back up state securely before switching computers. A fresh clone does not include state or live resources. Never apply into existing guide2/3 resources without reconciling their actual ownership/state; this acceptance required those resources to be absent.

On Windows set `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8` in the shell before running cloud helpers, so AWS CLI JSON containing report text survives console encoding. PowerShell must quote complete Terraform options such as `'-var-file=../../.local/showcase/workers.tfvars.json'`.

## Build and initialize

All commands below run from the repository root. Replace capitalized placeholders; they are not executable values.

1. Sync the locked API workspace: `uv sync --project backend --locked --package api`. Create a private `.local/showcase/admin-input.json` with `{"cluster":"YOUR_CLUSTER_ARN","secret":"YOUR_ADMIN_SECRET_ARN","database":"alex"}`. These are references, never a password. Run `uv run --project backend --locked --package api --with sqlparse deploy/showcase/environment.py preflight --admin-target .local/showcase/admin-input.json`. Privately inspect the inventory, credit eligibility, current usage and agreed allowance. The script is not a spending cap.
2. Run `uv run --project backend --locked --package api --with sqlparse deploy/showcase/environment.py database`. This creates only `alex_task11`, `alex_task11_app` and `alex-task11/database`; an existing initialization ledger is an inspection stop, not permission to overwrite. Then `uv run --project backend --locked --package api deploy/showcase/environment.py market --pg-bin PG_BIN_DIRECTORY` creates a SCRAM-protected loopback cluster on55441. Do not run as the OS root user on Linux.
3. Set `MASSIVE_API_KEY` or the supported legacy `POLYGON_API_KEY` in ignored root `.env` (see [provider setup](../../backend/market_data/README.md)). Run `uv run --project backend --locked --package api deploy/showcase/refresh_market.py`. Inspect private backfill evidence: require successful coverage for every selected symbol; do not replace failed fetches with generated prices.
4. Build the Linux dependency runtime: `uv run --project backend/reporter --locked backend/reporter/package_docker.py` (without `--deploy`). It writes `backend/reporter/reporter_lambda.zip`. Record that file's SHA256 and run `uv run --no-project deploy/showcase/build_workers.py --runtime-zip RUNTIME_ZIP --runtime-sha256 EXPECTED_SHA256`. All five workers share this locked Reporter dependency runtime, overlaid with current worker/database/research Python sources. A changed dependency set requires rebuilding and actual runtime probes; a matching ZIP hash alone is not proof of compatibility.
5. Build ingestion with `uv run --project backend/ingest --locked backend/ingest/package.py`. Initialize `terraform/2_sagemaker`, `terraform/3_ingestion` and `terraform/11_showcase` separately. Configure guide2 with `aws_region="us-east-1"`; guide3 also needs `sagemaker_endpoint_name="alex-embedding-endpoint"` in their ignored tfvars.

Use `terraform -chdir=terraform/DIRECTORY init` for each directory. For providers that cannot read a CLI browser-login profile, `uv run --no-project deploy/showcase/terraform_run.py DIRECTORY plan -out=../../.local/showcase/NAME.tfplan` exports credentials into the child process only. Privately inspect saved plans with `terraform -chdir=terraform/DIRECTORY show PLAN_PATH`; Terraform plan JSON and outputs can contain secrets. Require creation-only changes, and verify all names were absent before applying. Apply each reviewed saved plan with the same wrapper; do not use an unreviewed blanket apply. The accepted guide2/3 plans added6/20 resources.

After guide2/3 apply, run `uv run --project backend --locked --package api deploy/showcase/configure.py --clerk-jwks-url https://YOUR_CLERK_DOMAIN/.well-known/jwks.json`. This generates `.local/showcase/workers.tfvars.json`. Plan `11_showcase` with that var-file, review its23 additions, then apply the saved plan. The helper never starts Researcher or a schedule.

## Exercise the real flow

1. `uv run --project backend --locked --package api deploy/showcase/verify_cloud.py workers` checks deployed ZIP hashes and native imports without paid agent execution, and saves queue/worker outputs privately.
2. Obtain one genuine attributed Researcher record using [Task6's runbook](../../docs/verification/task-06-aws-acceptance.md), or privately restore the previously captured record. Supply a one-element JSON array containing `id`, `text`, and `metadata.sources` with original URLs/capture times. Do not invent provenance. Run `uv run --project backend/reporter --locked deploy/showcase/verify_cloud.py research --captured-research PRIVATE_RECORD_JSON`. This performs real ingestion, embedding and vector retrieval while preserving the original identity/time; it is not another Researcher browser run.
3. Configure ignored `frontend/.env.local` with the matching `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `NEXT_PUBLIC_API_URL=http://localhost:8000`. Start `uv run --project backend --locked --package api deploy/showcase/api.py` with API logs redirected privately. In another terminal run `npm ci`, then `npm run dev -- --hostname 127.0.0.1` from `frontend/`. Set `NEXT_TELEMETRY_DISABLED=1` if telemetry configuration is unavailable. The API verifies its dedicated database/secret before listening.
4. Open `http://localhost:3000/dashboard` in a normal browser and sign in through Clerk. Do not disable authentication or export browser tokens. After `/api/user` succeeds and exactly one user exists in the isolated database, run `uv run --project backend --locked --package api deploy/showcase/fixture.py`. It labels fictional holdings (AAPL1, MSFT2, cash1000) and performs one real Tagger classification preflight. It refuses to overwrite accounts or rerun an existing fixture ledger.
5. Open Market Data, inspect AAPL's source/date/history, and open Advisor Team. Click **Start New Analysis once**. Confirm the saved report, charts and retirement output. Run `uv run --project backend --locked --package api deploy/showcase/verify_analysis.py` to verify the persisted snapshot, chart values and research provenance. Pending or failed jobs are not acceptance success. The queue sends failed work to the DLQ after one receive; inspect it rather than generating unbounded model retries.

The demonstration must label sample holdings. Read-only verification does not require another analysis invocation. Tagger is a separate preflight; Planner orchestrates Reporter, Charter and Retirement. Record any auth failure and later successful requests honestly; do not treat every403 as expiration.

## Archive and clean up

Stop further user analysis requests. Run `uv run --no-project deploy/showcase/cleanup.py archive`, then `uv run --no-project deploy/showcase/archive_cloud.py`. These retain private table exports, a PostgreSQL custom dump, scoped CloudWatch logs and account/model-window usage observations. Preserve raw market files and artifact hashes. Public evidence must omit tokens, Clerk/user IDs, AWS account numbers, raw research and financial account totals.

Stop the owned API process. In reverse order **11_showcase → 3_ingestion → 2_sagemaker**, create saved `terraform plan -destroy` plans with the same variables. Inspect their complete resource lists against the original creation plans and inventory before applying. The accepted states contained23+20+6 resources, not the original application. Do not run the course's blanket database destroy. If a nonempty owned vector index/bucket prevents deletion, archive its contents and remove only those reviewed owned contents before retrying that same plan.

After the workers are gone, run `uv run --no-project deploy/showcase/cleanup.py database`. It requires the matching archive/ownership markers, removes only the dedicated database/login, schedules its secret for seven-day recovery deletion, and verifies the original database and Lambda versions. It can resume partial deletion while rechecking every remaining object's marker. Stop the local database with `uv run --no-project deploy/showcase/cleanup.py market`, and stop only the frontend/browser helper processes started for the demo.

Inspect all three Terraform states for emptiness and independently check resource absence. SageMaker may automatically create `/aws/sagemaker/Endpoints/alex-embedding-endpoint` outside Terraform: archive it, then delete it only if its exact name and creation timestamp establish that this acceptance owns it. Preserve pre-existing service-linked roles, original application resources and the separate Task10 IAM/OIDC/empty ECR setup.

## Retention and tests

The public deliverable is source, runbooks, redacted results and a short **evidence walkthrough**, not an always-on endpoint. The walkthrough is generated from checked results and is explicitly not a Brave screen recording. Private dumps/logs/source responses remain local until securely transferred or deliberately deleted; GitHub clone alone cannot restore them. Rebuild/revalidate later using your own keys and reviewed plans.

Offline checks: `uv run --no-project -m unittest discover -s deploy/showcase -p 'test_*.py' -v`; `terraform -chdir=terraform/11_showcase test` uses a mock provider and creates no AWS resources. Frontend regression: `npm run test:dashboard` from `frontend/`. The cloud verifier commands above do contact real AWS; only the fixture and analysis steps invoke paid agents.
